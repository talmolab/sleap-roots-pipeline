Open & blocked

bloom #685

Write-back RPC will reject every new envelope once the traits image redeploys.

insert_cyl_result_envelope hard-pins contract_version to exactly 0.1.0a3. Traits just bumped its own pin to a7 (#263, already merged) — the RPC has no idea a7 exists. Not urgent until that image is actually redeployed, but it will silently reject 100% of scans the moment it is. Open since 2026-08-14, still unowned, zero comments.

#37 (gap 4)

The run manifest never actually reaches write-back in production — a losing concurrent batch could silently lose real results.

Predict doesn't copy run_manifest.json forward into its own output (confirmed: no such code in batch.py), so traits' manifest-consumption sees "absent" and falls back to unscoped in every real run today. Separately, traits' own copy_run_manifest_forward is a naive copy with no lock, unlike bloomctl's origin-stage handling — two concurrent batches sharing an output dir could clobber each other's scan_keys. Harmless while nothing downstream consumed the manifest; no longer harmless now that write-back scopes its own discovery to it (bloom #697, merged 2026-08-19). Found 2026-08-19, filed as a comment on #37, flagged on bloom PR #697 — still unaddressed, unowned.
